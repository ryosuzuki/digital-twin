02 / Yes: raycast the center — その方式です

YOLOは物体のクラスと2D矩形を出します。矩形の中心から校正済みrayを飛ばし、環境深度のヒット点を近似位置として使います。

  1. Detect: 640×640画像からクラス・スコア・矩形。
  2. Project: 上原点を下原点へ変換し、中心UVからworld rayを求める。
  3. Hit: MRUKの環境深度へraycast。距離を固定値で仮定しない。
  4. Annotate: hit点を通るカメラ平行平面へ四隅を投影し、線とラベルを配置。
var ray = cameraAccess.ViewportPointToRay(
    new Vector2((left+right)/2, (bottom+top)/2), capturedPose);
if (!environmentRaycast.Raycast(ray, out var hit, 12f)) continue;
var plane = new Plane(capturedPose.rotation * Vector3.forward, hit.point);

実際のQuestYolo.csのDraw()から抜粋。capturedPoseは画像取得時に保存した撮影時カメラ姿勢です。

中心rayが背景に当たることもあります。
椅子の穴や人の脚の間では、検出矩形の中心は実物の表面とは限りません。深度は物体クラスを理解していません。次の拡張は複数rayの深度集約やマスクですが、現版には未実装です。

03 / Detection ≠ tracking ≠ anchors

概念問い0.2.0
2D detectionこの画像に何がある？実装済み
3D localization世界のどこへ表示する？中心ray + 深度で近似
Temporal object tracking前フレームと同じ物体？未実装。永続track IDなし
Head tracking頭がどこを向いている？Metaの位置追跡を使用
Persistent anchors再起動後も同じ場所？未実装。保存・共有なし

現版は検出ごとにannotationを作り直し、0.85秒以上更新がなければ消します。要求上限5Hzは、実更新5FPSやXR描画FPSの保証ではありません。

XR objectへ拡張するなら: trackId / class / position / confidence / lastSeenの状態を持ち、過去の検出と対応付けます。動く物体の追跡と、空間に固定されたアンカーは別の設計です。これは今後の課題であり、現版の実装済み機能ではありません。

XR-Objects — 物体を「操作できる」ようにする

ここでいうXR-Objectsは、Augmented Object Intelligence with XR-Objects（UIST 2024 / DOI）。一般的なXRのGameObjectではありません。

検出 → 深度raycast → object proxy → context menu → 情報・比較・共有・ノート／タイマーという、物体にデジタルな操作を結び付ける仕組みです。

段階XR-Objects論文このQuest版
FindMediaPipe / COCO80本体YOLO
LocalizeARCore深度 + raycastMRUK深度 + 中心ray
PresentObject proxy + context menu枠 + クラス名
Act / reason物体別のcloud PaLI / 各種actions未実装。メニュー・選択・会話なし

論文Figure 4 / §3.3（pp.5–7）はスマートフォンのUnity AR Foundation / ARCore実装です。Questで全機能がローカルに動いた証拠ではありません。

次の一歩: 中心rayのhit点にPrefabを置く → controller/hand rayで選ぶ → 物体に結び付いたメニューを開く。現版は検出と位置合わせの足場であり、XR-Objectsの完全再現ではありません。

04 / Build it — 自分で動かす

Unity native: 一人称ARはこちら

# digital-twin のルート。出力先は存在しない場所。
python3 implementations/quest-ondevice-yolo/scripts/prepare-unity.py /absolute/new/quest-yolo-unity
  1. Git LFSとAndroid Build Supportを用意。
  2. 生成先をUnity 6000.4.5f1で開く。
  3. Classroom → Prepare YOLO scene → Build Android APK。
  4. Quest 3/3Sに導入し、カメラ・空間データの許可と位置追跡を確認。
  5. Classroom Local YOLOを開く。Package: org.openclaw.classroom.yolo。

MRUK 85.0.0 / Inference Engine 2.6.1 / OpenXR 1.16.1が今回の検証済み構成。取得元は固定コミットとモデルhashで確認します。

Web: まずはローカル物体検出

cd implementations/quest-ondevice-yolo/web
npm ci
npm run prepare-assets
npm test
npm run dev

Load model → カメラまたはローカル画像。Quest配布には信頼されたHTTPSが必要です。WebXRのパススルー表示は、JavaScriptによるカメラ画素取得の保証ではありません。Web版は映像パネル表示で、Unityと同等の位置合わせではありません。

06 / Try in class

  1. threshold 0.35と0.6で、見落とし・誤検出を比較する。

  4. ログのinference_ms / depth_hits / trackedを観察する。
