01 / Recognition input is not display

No camera-preview panel. No detection rectangle.
Meta compositor passthrough supplies the physical view. The app places only text labels under native spatial anchors.

YOLO runs on Quest's built-in GPU through Unity Inference Engine 2.6.1. Passthrough Camera API supplies RGB; MRUK 85.0.0 supplies environment-ray hits; OVRSpatialAnchor retains each initial hit location.

02 / Center-depth hit → native anchor → label

  1. Normalize the detected box and convert image coordinates into camera viewport coordinates.
  2. Use a calibrated ray with the exposure-time camera pose.
  3. Raycast into environment depth. No hit means no new label.
  4. Place an independent root once at the hit and add OVRSpatialAnchor.
  5. Wait for Localized and IsTracked; do not show or count pending/failed anchors.
  6. Rotate only the text child to face the viewer. Later detections do not reposition the root.
var ray = cameraAccess.ViewportPointToRay(centerUV, capturedPose);
if (!environmentRaycast.Raycast(ray, out var hit, 12f)) continue;
// New object only; abbreviated from Observe():
var root = new GameObject("ObjectAnchor_" + nextId);
root.transform.SetPositionAndRotation(hit.point, Quaternion.identity);
itemNew.anchor = root.AddComponent<OVRSpatialAnchor>();

Complete QuestYolo.cs includes association and readiness gates; this excerpt is not standalone.

A fixed surface point is not a moving object's center.
The ray can hit background through a chair opening. An anchor can faithfully retain an initially wrong location. This sample does not reconstruct exact 3D geometry or track moved objects.

03 / Stable location, honest scope

  • Same-class detections match one-to-one within 0.65m; later observations update confidence and last-seen time, not anchor position.
  • Maximum 20 records; retain unobserved locations for 30 seconds.
  • A: freeze/resume observations while anchors remain. B: clear anchors.
  • Focus/head-tracking loss hides labels without deleting records. Native localization/tracking must be valid to show them again.
  • Session-local only: no disk save, sharing, or restoration after restart.
  • The text child billboards by rotation only; the anchor root is never driven by the head.

Class/proximity matching can confuse nearby same-class objects. It is not a general moving-object tracker.

Connecting to XR-Objects

Augmented Object Intelligence with XR-Objects (UIST 2024) uses object localization as the foundation for object-bound interfaces. Its evaluated phone prototype combines AR Foundation/ARCore, MediaPipe, and cloud PaLI. Our immediate goal is the stable label itself: no menus, selection, conversation, or cloud reasoning are implemented.

06 / Inspect retention, not just detections

  1. Look for stable record IDs and native UUIDs across inference updates.
  2. Freeze observations and check that localized/tracked labels remain.
  3. Compare anchor position and headset pose logs without confusing them.
  4. Identify initial depth hits on background.
  5. Treat moving-object tracking and saved cross-relaunch persistence as separate tasks.

Developer-only launch extra classroom_demo_freeze_after (float, default0) freezes after a real observation interval; HUD/logs explicitly report the frozen phase. It never fabricates detections.
