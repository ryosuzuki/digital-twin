01 / The pipeline — what runs where?

The camera is recognition input. There is no camera-preview panel.

No external GPU does not mean no GPU. Unity inference uses Quest's built-in GPU. Initial SDK and model downloads aside, no inference server is needed.

02 / Yes: raycast the center

YOLO returns an object's class and 2D box. A calibrated ray through the box center intersects environment depth to estimate its position.

  1. Detect: Class, score, and box from a 640×640 image.
  2. Project: Convert top-origin to bottom-origin coordinates, then map center UV to a world ray.
  3. Hit: Raycast into MRUK environment depth. Do not guess a fixed distance.
  4. Annotate: Project four corners onto a camera-parallel plane through the hit, then draw lines and a label.
var ray = cameraAccess.ViewportPointToRay(
    new Vector2((left+right)/2, (bottom+top)/2), capturedPose);
if (!environmentRaycast.Raycast(ray, out var hit, 12f)) continue;
var plane = new Plane(capturedPose.rotation * Vector3.forward, hit.point);

Actual QuestYolo.cs, Draw() excerpt. capturedPose is the exposure-time camera pose saved when acquiring the frame.

The center ray can hit background.
A chair opening or gap between a person's legs may put the box center behind the object. Depth does not identify object classes. Multiple depth samples or masks are possible extensions, not current features.

03 / Detection ≠ tracking ≠ anchors

ConceptQuestion0.2.0
2D detectionWhat is in this image?Implemented
3D localizationWhere should content appear in the world?Approximate center ray + depth
Temporal object trackingIs this the same object as before?Not implemented; no persistent track IDs
Head trackingWhere is the headset pointing?Uses Meta positional tracking
Persistent anchorsSame place after restart?Not implemented; no saving or sharing

Annotations are recreated after each detection and expire after 0.85 seconds without updates. A requested maximum of 5Hz guarantees neither 5 detection FPS nor XR rendering FPS.

To build an object record: Store trackId / class / position / confidence / lastSeen and associate new observations with past detections. Moving-object tracking differs from a fixed spatial anchor. These are proposed extensions, not implemented features.

XR-Objects — make physical objects actionable

Here XR-Objects refers to Augmented Object Intelligence with XR-Objects（UIST 2024 / DOI), not a generic XR GameObject.

Detect → depth raycast → object proxy → context menu → information, comparison, sharing, notes/timers: attach digital actions to physical objects.

Paper Figure 4 / §3.3 (pp.5–7) describes a smartphone Unity AR Foundation / ARCore implementation. It is not evidence that all features run locally on Quest.

Next step: Place a Prefab at the center-ray hit → select it with a controller/hand ray → open an object-bound menu. The current sample is a detection/localization foundation, not a full XR-Objects reproduction.

04 / Build it — run the sample

Unity native: start here for first-person AR

# From the digital-twin root. Use a destination that does not exist.
python3 implementations/quest-ondevice-yolo/scripts/prepare-unity.py /absolute/new/quest-yolo-unity
  1. Install Git LFS and Android Build Support.
  2. Open the generated project in Unity 6000.4.5f1.
  3. Classroom → Prepare YOLO scene → Build Android APK。
  4. Install on Quest 3/3S; grant camera/spatial-data permissions and establish positional tracking.
  5. Open Classroom Local YOLO. Package: org.openclaw.classroom.yolo.

The verified stack is MRUK 85.0.0 / Inference Engine 2.6.1 / OpenXR 1.16.1. Source commit and model hash are pinned.

Web: start with local detection

cd implementations/quest-ondevice-yolo/web
npm ci
npm run prepare-assets
npm test
npm run dev

Load model → camera or local image. Quest distribution requires trusted HTTPS. A WebXR passthrough view does not guarantee JavaScript camera-pixel access. The Web sample displays a video panel, not the native sample's spatial overlay.
